## Review

- **Correct:** Operator override APIs require `familyId`/target/reason, enforce operator/admin/root roles, capture the authenticated actor, validate family/supplier boundaries, and persist actor/reason/timestamp evidence (`resource-actions.ts:1176-1221`, `company-product-family-service.ts:237-302,620-630`).
- **Correct:** Unresolved lines retain ASIN/SKU and quantity, remain visible in order planning, and are excluded from Gold inventory calculations.
- **Correct:** `skipGoldRefresh` is propagated by `runCsvBundleImport` and supplied for the seven medallion bootstrap import paths. Sellerboard COGS does not receive it.

- **Blocker:** Clean bootstrap ordering is invalid. Order Management runs at `scripts/live-gate-bootstrap.mjs:299-307`, and ClickUp requires matched orders at `:310-344`, but supplier authority is not imported until stages 7/8 after `:399`. The normalizer refuses order rows whose supplier reference has not already been established (`medallion-normalization-service.ts:164-185`). A clean run therefore cannot reliably create orders before ClickUp. **Minimal fix:** import authoritative Supplier Management data before Order Management, then run ClickUp; retain a later explicit unresolved-product reconciliation after Sellerboard.
- **Blocker:** Sellerboard completeness checks are not wired into production. `preflightImportFiles` only evaluates coverage when optional arguments are supplied (`import-preflight.ts:444-447`), while the bootstrap still calls the existing `preflightData()` at `live-gate-bootstrap.mjs:286`; no changed production caller supplies coverage. Tests call the helper directly and therefore do not prove the release gate. **Minimal fix:** have bootstrap preflight construct four-company account/marketplace/freshness/history coverage and pass it to the preflight implementation.
- **Blocker:** Phase A SQL does not establish the claimed Silver→Gold boundary. `validateSilverPhase()` checks only `goldInventoryPlanningRows`, although Phase B rebuilds multiple Gold read models. Its authority-leakage check also rejects only datasets containing “top sku” or “buybox”, rather than positively proving product/company-product links came from approved Sellerboard sources. **Minimal fix:** assert every rebuilt Gold table is empty and join normalization links through import runs/source connections to allow only explicit Sellerboard authority.
- **Blocker:** Amazon identity authority is broader than exact source identity: `createsAmazonIdentity` accepts any non-supplier record whose `sourceType` equals `sellerboard` (`medallion-normalization-service.ts:138-139`). This does not authenticate the approved adapter/dataset boundary. **Minimal fix:** use an explicit approved Sellerboard dataset/adapter allowlist derived from the import run/source connection.
- **Blocker:** `20260713200000-add-order-line-source-identity.ts` is untracked. Even if migration discovery is directory-based, it will not ship unless added to Commit C. Its registration/execution therefore cannot currently be accepted.
